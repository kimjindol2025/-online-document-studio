# GitHub 양식 감시

사용자의 `add-30-forms` 브랜치를 주기적으로 읽고 변경된 JSON을 검사한 뒤 FG의 같은 브랜치로 소스를 동기화한다. `main` 병합·사이트 게시·양식 본문 자동 생성·외부 메시지 발송은 하지 않는다. 현재 검증된 작성기는20종으로 유지한다.

최초 확인 시 신규 정의는36개였고26개는 내용1칸뿐이며33개는 빈 작성본도 통과했다. 이후 브랜치가 계속 갱신되고 있어 최신 수량은 status.json/status.md를 기준으로 확인한다. 이 수치를 완성된36개 양식으로 계산하지 않는다. 문서별 필드가 없는 기본 틀은 DRAFT, 기본 구성이 갖춰진 정의도 FUNCTIONAL_REVIEW_NEEDED다. 후자는 법적 적정성이나 브라우저/파일 출력을 검증했다는 뜻이 아니다.

```bash
node tools/watch-github-forms.mjs --once --mirror --state-dir /별도/작업기록
node tools/watch-github-forms.mjs --watch --mirror --interval-seconds 300 --state-dir /별도/작업기록
```

- 원격은 실제 URL의 호스트/저장소를 확인한다. GitHub `kimjindol2025/-online-document-studio`, FG `kim/online_document`로 제한한다.
- 읽는 브랜치에서 바뀐 경로가 definitions의 JSON뿐인지, 크기/파싱/스키마/중복ID/비밀 패턴을 확인한다. 한글 파일명도 NUL 구분 Git 경로로 읽고, 현재 스키마가 허용하지 않는 한글 ID 등은 별도 오류로 보고한다. 원격 JavaScript·쉘·Git 후크를 실행하지 않는다.
- 기존 Node Git/프로세스/파일/타이머 통합 어댑터이며 FreeLang 도메인 로직은 변경하지 않는다.
- JSON 초안/스키마 오류가 있는 소스도 작업 브랜치 백업으로는 동기화한다. 앱에 게시하거나 검증 완료로 표시하지 않는다. 정의 이외 파일, 비밀 패턴, 과도한 파일 크기는 원격 변경을 막는다.
- FG는 fast-forward만 허용하고 푸시 후 원격 ref를 대조한다. 외부 변경이 한번 실패하면 자동 변경 재시도를 중지한다. 조회는 계속하며 실패 이유를 상태 파일에 기록한다.
- status.json, status.md, history.ndjson과 실행 PID를 기록한다. 암호·토큰·쿠키를 읽거나 결과에 저장하지 않는다.
- 각 FG Git 작업 전에 인증 파일의 읽기 가능 여부와600 권한만 확인한다. 파일 내용은 읽지 않는다.
- 주기 기본값은5분, 최솟값1분이다. 알림을 채팅이나 GitHub 댓글로 전송하는 기능은 없다.
- 검증/승격은 별도 단계다. 문서별 필수 구성과 실제 브라우저/출력 검사를 완료한 뒤 작성기에 반영한다.

현재 실행 PID와 로그·마지막/다음 확인은 작업 기록 경로에서 확인한다. 감시기를 중지할 때는 PID가 해당 스크립트인지 확인한 후 그 프로세스만 종료한다. 운영 서비스와 정적 테스트 서버는 별도 프로세스다.
